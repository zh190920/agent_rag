# 报告撰写流程（Report Writer）

本技能指导你在**只读文件工具**约束下，把授权目录里的原始文档整理成一份可核对的
技术报告/问答总结。核心原则：**无原文不结论，有结论必引用**。

## 适用判断

出现以下意图即适用本技能：

- 「总结一下 X」「梳理 Y 的架构」「对比 A 和 B」
- 「基于知识库/文档回答……并给出出处」
- 任何需要**引用原文**、不能凭空作答的知识任务

## 执行步骤

1. **摸底**：先用 `list_dir` / `glob` 看清授权目录里有哪些文档；文件多时用 `find`
   按名称或修改时间筛出候选（如只看 `*.md`、只看最近改动的）。
2. **定位**：对候选主题，用 `grep` 搜索关键词，拿到「文件:行号」命中列表；
   需要上下文时给 `grep` 传 `context`，命中过多用 `skip` 分页续读。
3. **精读**：对最相关的片段用 `read_file`（带 `offset`/`limit`）读全上下文，
   确认语义后再落笔，**不要只凭 grep 的一行断章取义**。
4. **成文**：按下述结构组织；每条关键论据后面标注来源 `文件名:行号`。
5. **自检**：逐条核对引用是否真能在原文对应行找到；证据不足处显式写「未找到依据」。

## 输出结构

```
## 结论（TL;DR）
2-4 句直接回答，含最关键的量化事实。

## 关键论据
- 论点一 —— 支撑原文摘要（文件名:行号）
- 论点二 —— ……（文件名:行号）

## 待核实 / 局限
证据不足或存在歧义的点，如实列出。
```

详细的引用书写与措辞规范见随附参考：`references/output-checklist.md`
（相对 `${SKILL_DIR}`，需要时用 `read_file` 读取）。

## 红线约束

- 只读授权目录内的文件；越权路径会被拒绝，不要反复尝试。
- 每条结论都要能回链到 `文件名:行号`；给不出引用就标注「无原文依据」。
- 证据不足时如实说明，**严禁编造**行号或内容。
